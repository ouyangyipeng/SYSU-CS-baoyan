# 计算机网络面试题
# 计算机网络

 

### 1\. 什么是计算机网络?它的基本功能是什么?

 

计算机网络是一组通过通信链路连接起来的计算机系统，它允许计算机之间共享资源和信息。基本功能包括

 
1. 资源共享:如打印机、文件、网络存储等。
 
2. 信息传递:通过电子邮件、聊天、文件传输等。
 
3. 远程访问:允许远程计算机访问网络中的资源
 
4. 通信:提供多种通信方式，如语音、视频通话等
 

### 2\. 计算机网络为什么要分层，分层的优点是什么?能否举网络分层模型的例子?

 

> 人话：计算机网络是个非常复杂的系统，分层可以将庞大复杂的问题，转化成若干个较小的局部问 题，这些局部的较小的问题就比较易于研究和处理。有如下优点：
> 
>  
> - 各层之间是独立的，不用关心其他层次的内容；
>  
> - 灵活性好，任何一层发生变化不影响上下层；

 

计算机网络的分层设计是为了提高网络系统的效率、可管理性和可扩展性。分层的主要优点包括

 
1. 简化设计和实现:通过将复杂的网络功能分解成多个层次，每层只负责特定的功能，使得每层的设计和实现更加简单。这种分层结构使得网络设计更为模块化，每层的开发人员只需关注自己负责的功能。
 
2. 提高可维护性:分层使得网络系统的各个部分可以独立开发和测试。一旦某一层的功能实现完成，可以在不影响其他层的情况下进行修改或优化。这种隔离性减少了系统修改时可能引入的错误。
 
3. 方便故障排除和调试:由于网络系统被分成多个层次，故障排查可以在特定层次上进行，这样更容易定位问题的根源。例如，可以先检查物理层的问题，再检查传输层的问题。
 
4. 促进标准化:每一层都有清晰的功能和接口标准，这有助于不同厂商和开发者的系统之间的兼容性和互操作. 性。标准化的接口允许不同厂商的设备和软件可以顺利地进行集成和协作。
 
5. 支持多种网络协议:分层设计允许在不同的层使用不同的协议和技术。这样，网络系统可以支持各种不同的网络协议和技术，从而实现不同网络环境下的有效通信。
 

网络分层模型的例子:最著名的分层模型是OSI七层模型和TCP/IP四层模型。

### 4\. TCP/IP网络模型是什么？每一层的作用是什么？

 

TCP/IP网络模型是一种用于描述互联网协议族的分层模型，它将网络通信分为四个主要层次：应用层、传输层、网络层和网络接口层。以下是每个层次的作用：

 
1. 应用层：
 
- 功能：提供用户与网络之间的接口，支持各种网络应用，如HTTP（网页浏览）、FTP（文件传输）、SMTP（电子邮件发送）等。
 
- 协议示例：HTTP、FTP、SMTP、DNS。
 
2. 传输层：
 
- 功能：负责主机之间端到端的通信，提供可靠的数据传输服务，包括数据的分割与重组、流量控制和错误检测与纠正。
 
- 协议示例：TCP（传输控制协议）、UDP（用户数据报协议）。
 
3. 网络层：
 
- 功能：负责数据包从源主机到目的主机的传输，包括路由选择和数据包的转发。
 
- 协议示例：IP（互联网协议）、ICMP（互联网控制消息协议）。
 
4. 网络接口层：
 
- 功能：处理与物理网络介质相关的细节，包括数据的封装、解封装、物理地址的识别以及数据的发送和接收。
 
- 协议示例：以太网协议、Wi-Fi协议、PPP（点对点协议）。

- 分层思想一致：OSI和TCP/IP都采用了分层的架构来组织网络通信，体现了分层设计的思想。

### 6.物理层的主要功能是什么？

 

物理层是OSI七层模型的最底层，也是TCP/IP四层模型中的网络接口层的一部分。它的主要功能包括：

 
1. 定义物理接口标准：包括连接器的形状和尺寸、引脚数量和排列、电气特性（电压、电流等）以及光学特性（对于光纤通信）。
 
2. 传输原始比特流：将来自数据链路层的信号转换为可以在传输介质上传输的物理信号（如电信号、光信号）。
 
3. 同步：确保发送方和接收方的时钟同步，以便正确地解释接收到的信号。
 
4. 信号编码：将数字数据转换为适合传输介质的模拟或数字信号。
 
5. 错误检测：通过物理层的编码技术，如曼彻斯特编码，可以在物理层进行基本的错误检测。
 

### 7\. 数据链路层的主要功能是什么？

 

数据链路层负责将物理层提供的比特流封装成帧，进行帧的发送和接收，处理链路上的错误检测和纠正，以及流量控制。它确保数据在单个链路上传输时的可靠性。

 

### 8\. 什么是MAC地址?它与IP地址的区别是什么?

 
- MAC地址:是网络接口卡(NIC)硬件上标识设备的唯一地址，通常由48位(6字节)组成，用于数据链路字
 
- IP地址:是网络层分配的地址，用于标识网络中的设备，并进行路由选择。IPv4地址是32位(4字节)，IPv6地址是128位(16字节)。
 
- 区别:MAC地址是物理地址，唯一目固定;IP地址是逻辑地址，可在网络中配置和更改，用于网络层路由。
 

### 9.网络层的主要功能是什么？

 

网络层负责数据包的路由选择、逻辑地址分配和网络间的数据传输。它将数据从源主机传送到目标主机，并进行路径选择和流量控制。

 

### 10\. 网络层常见的协议有哪些？简要介绍一下

 

网络层是OSI七层模型中的第三层，负责在网络中的不同节点之间传输数据包。网络层常见的协议包括：

 
1. \*\*IP（Internet Protocol）\*\*‌：
 
- IPv4：是最常用的版本，使用32位地址，能够提供约43亿个地址。
 
- IPv6：为了解决IPv4地址耗尽的问题而设计，使用128位地址，提供了更多的地址空间。
 
2. \*\*ICMP（Internet Control Message Protocol）\*\*‌：
 
- 用于发送控制消息，如错误报告和网络查询，帮助网络设备诊断和解决网络问题。
 
3. \*\*ARP（Address Resolution Protocol）\*\*‌：
 
- 用于将网络层的IP地址解析为数据链路层的MAC地址，以便数据能够在网络中传输。
 
4. \*\*RARP（Reverse Address Resolution Protocol）\*\*‌：
 
- 与ARP相反，用于将MAC地址解析为IP地址，通常用于无盘工作站获取自己的IP地址。
 
5. \*\*IGMP（Internet Group Management Protocol）\*\*‌：
 
- 用于管理多播组成员资格，允许主机报告它们希望加入或离开特定多播组的意愿。
 
6. \*\*OSPF（Open Shortest Path First）\*\*‌：
 
- 是一种链路状态路由协议，用于在大型企业网络和互联网服务提供商网络中计算最佳路径。
 
7. \*\*BGP（Border Gateway Protocol）\*\*‌：
 
- 是一种路径矢量路由协议，用于在不同的自治系统（AS）之间传播路由信息，是互联网的主要路由协议。
 

这些协议在网络层中扮演着至关重要的角色，确保数据包能够有效地在网络中传输，无论是在局域网还是广域网中。

 

### 11\. 什么是 IP 协议

 

网际协议 IP(Internet Protocol)协议用于在相互连接的网络之间传递 IP 数据包。如果数据包不 能直接发送到目标主机，那么 IP 协议就会为它寻找下一个合适的路由器，并将数据包交付 给该路由器来转发。多次重复这一过程，数据包最终到达目标主机，或由于发送失败而被丢 弃。

 

IP 协议的特点是：无连接，不可靠，无状态

 
- 无连接是指：IP 通信的双方都不长久地维持对方的任何信息。这样的话，上层协议每 次发送数据的时候，都必须明确地指定对方的 IP 地址。
 
- 不可靠是指：IP 协议不保证数据报能够准确无误的到达接收端，它只能尽最大努力去 传送。
 
- 无状态是指：通信双方不同步传输数据的状态信息，也就是 IP 数据报的发送传输，接 收都是相互独立的，没有上下文关系。那么接收端就可能收到重复的，乱序的报文段。 这就是所谓的无状态。
 

### 12\. 什么是环回地址

 

环回地址也称 localhost，是网络号为 127.0.0.0/8 的地址，当网络应用程序需要与本地主机进 行通信时，可以使用环回地址来模拟发送和接收数据的过程，而无需通过网络设备进行实际 的网络传输。

 

### 13\. 什么是 ICMP 协议

 

基本概念

 

网络层使用 ICMP（Internet Control Message Protocol）网际报文控制协议允许主机或路由器 报告差错或进行询问 差错报告报文分为：终点不可达、时间超过、参数问题、改变路由 询问报文分为：回送请求、时间戳请求

 

ICMP 应用

 
- 分组网间探测（ping)，用来测试两台主机间的连通性。 通过发送ICMP Echo请求消息到目标主机，并等待目标主机返回ICMP Echo响应消息， 可以确定目标主机是否可达以及网络延迟情况。
 
- 追踪路由（tracert），用来跟踪一个分组从源点到终点的路径
 

### 14\. 什么是路由选择协议

 

基本概念

 
- 路由选择协议规定了互联网中的路由器如何交换信息并生成路由表。
 
- 由于互联网规模很大，并且有的单位不希望外界了解其网络的布局细节，可以把互联网 分为许多较小的自治系统(Automous system, AS)。
 
- 内部网关协议(Interior Gateway Protocol)：在 AS 内部使用的路由选择协议。
 
- 外部网关协议(External Gateway Protocol)：在不同 AS 间使用的路由选择协议。
 
- IGP 和 EGP 是路由选择协议的分类名称，而不是具体的路由选择协议。
 
- AS 之间的路由选择叫做域间路由选择，AS 内部的路由选择叫做域内路由选择。
 

### 15\. 什么是 RIP 协议

 
- RIP(Routing Information Protocol)是一种基于距离向量的路由选择协议，距离向量是指 每一个路由器都维护自己到其他每一个目的网络的距离。
 
- RIP 协议特点：仅和相邻路由器交换信息、交换的信息是当前路由器知道的全部信息即 路由表、按固定时间间隔交换信息。
 
- 存在坏消息传的慢的问题，当网络出现故障时，要经过较长时间才能将信息传递到所有 路由器。
 

### 16\. 什么是 OSPF 协议

 

OSPF(Open Shortest Path First)是一种基于链路状态的路由选择协议。链路状态是指本路 由器和哪些路由器相邻。

 

OSPF 特点：

 
- 向所有路由器发送链路状态，最终构建出一个链路状态数据库，即整个网路的拓扑 图，再使用 Dijkstra 求出最优路径。
 
- 可以用于很大的网络，将一个 AS 划分为若干更小的区域，洪泛法局限于一个区域 而不是 AS，一个区域内的路由器只知道本区域内的完整拓扑，减少了网络的通信量。
 
- 可以为不同的链路指定不同的代价
 
- 有多条代价相同的路径时可以进行负载均衡
 

### 17\. 什么是 BGP 协议

 
- BGP(Border Gateway Protocol)是一种用于在不同自治系统（AS）之间交换路由信息的 外部网关协议（EGP）
 
- 由于各 AS 内度量路由的代价各不相同，BGP 只是力求找到一条比较好的路由，而不是 最佳路由
 
- 不同 AS 内的发言人建立 TCP 连接后交换路由信息，发言人构造出一个树形结构的自 治系统连通图

### 19\. IP寻址是如何工作的？

 
1. IP地址分配：
 
- 每台连接到网络的设备都会被分配一个唯一的IP地址。对于IPv4，这是一个32位的二进制数，通常表示为四个十进制数，每个数介于0到255之间，用点分隔（如192.0.2.1）。
 
- 对于IPv6，地址是一个128位的二进制数，通常表示为八组四位的十六进制数，用冒号分隔（如2001:0db8:85a3:0000:0000:8a2e:0370:7334）。
 
2. 子网划分：
 
- 为了更有效地管理IP地址，网络通常会被划分为多个子网。子网划分通过子网掩码来实现，子网掩码也是一个32位（IPv4）或128位（IPv6）的二进制数，用于确定IP地址中哪些位用于网络部分，哪些位用于主机部分。
 
3. 路由决策：
 
- 当数据包从源设备发送到目的设备时，路由器会根据IP地址和子网掩码来决定数据包的传输路径。路由器会查找其路由表，找出与目的IP地址匹配的最佳路由，并将数据包转发到下一个跳点。
 
4. 地址解析：
 
- IP地址是逻辑地址，而网络设备实际上通过物理地址（如MAC地址）进行通信。因此，需要一个机制将IP地址解析为对应的物理地址。这通常是通过\*\*地址解析协议（ARP）\*\*来实现的。
 
5. IP地址分类：
 
- IPv4地址 traditionally被分为五类（A、B、C、D、E），其中A、B、C类用于单播通信，D类用于多播通信，E类保留用于将来使用。IPv6地址则使用更灵活的划分方式。
 
6. 私有地址与公有地址：
 
- 私有地址是在局域网内部使用的，不会被路由到互联网。公有地址则是全球唯一的，可以被路由到互联网。私有地址通过网络地址转换（NAT）技术可以在互联网上进行通信。
 

### 20\. ARP协议的作用是什么？

 

ARP（Address Resolution Protocol）协议的作用是将网络层的IP地址解析为数据链路层的MAC地址。在计算机网络中，IP地址用于在网络层标识主机，而MAC地址用于在数据链路层标识网络接口。由于IP地址和MAC地址分别位于不同的层次，它们之间没有直接的映射关系。ARP协议就是用来解决这个问题的。

 

ARP协议的工作原理如下：

 
1. ARP请求：
 
- 当一台主机需要向另一台主机发送数据时，它首先检查自己的ARP缓存，看是否有目的IP地址对应的MAC地址。
 
- 如果没有，它会构造一个ARP请求包，包含自己的IP地址和MAC地址，以及目的IP地址。然后，它会将这个ARP请求包广播到本地网络上的所有主机。
 
2. ARP响应：
 
- 本地网络上所有主机都会收到ARP请求包，但只有目的IP地址对应的主机才会响应。
 
- 目的主机收到ARP请求包后，会检查包中的目的IP地址是否与自己的IP地址匹配。
 
- 如果匹配，它会构造一个ARP响应包，包含自己的IP地址和MAC地址，然后将这个ARP响应包发送回请求主机。
 
3. ARP缓存更新：
 
- 请求主机收到ARP响应包后，会将目的IP地址和对应的MAC地址添加到自己的ARP缓存中。
 
- 以后，当请求主机再次需要向目的主机发送数据时，它可以直接从ARP缓存中获取目的主机的MAC地址，而无需再次发送ARP请求。
 

### 21.NAT协议的作用是什么？工作原理呢？

 

\*\*NAT（Network Address Translation）协议的作用主要是解决IP地址短缺问题，同时提高网络的安全性。\*\*NAT允许内部网络使用私有IP地址，而在与外部网络通信时，通过NAT设备将私有IP地址转换为一个或少数几个合法的公网IP地址。

 

NAT的工作原理如下：

 
1. 地址转换：
 
- 当内部网络中的设备尝试与外部网络通信时，NAT设备会拦截这些数据包，并将数据包中的源IP地址（私有IP地址）替换为NAT设备的公网IP地址。
 
2. 端口映射：
 
- 为了区分来自同一公网IP地址的不同内部设备的流量，NAT设备还会修改数据包的源端口号。这样，即使多个内部设备使用同一个公网IP地址，NAT设备也能根据端口号将返回的数据包正确地转发给相应的内部设备。
 
3. NAT表：
 
- NAT设备维护一个NAT表，记录了内部IP地址和端口号与公网IP地址和端口号之间的映射关系。当数据包从外部网络返回时，NAT设备会查找NAT表，将数据包的目的IP地址和端口号恢复为原来的内部IP地址和端口号，然后将数据包转发给正确的内部设备。
 
4. 安全性：
 
- NAT还提供了一定程度的安全性，因为外部网络无法直接访问内部网络的私有IP地址。此外，NAT隐藏了内部网络的结构，增加了外部攻击者识别和攻击内部设备的难度。
 

NAT有几种不同的类型，包括静态NAT、动态NAT和网络地址端口转换（NAPT）。静态NAT为内部网络中的每个设备分配一个固定的公网IP地址，而动态NAT则从一个地址池中分配公网IP地址。NAPT不仅转换IP地址，还转换端口号，允许多个内部设备共享一个或少数几个公网IP地址。

\*\*TCP（Transmission Control Protocol）\*\*是一种面向连接的、可靠的传输层协议。为了建立和终止一个TCP连接，TCP使用了三次握手（Three-Way Handshake）和四次挥手（Four-Way Wavehand）的过程。

 

TCP三次握手的过程如下：

 
1. 第一次握手（SYN）：
 
- 客户端发送一个SYN（同步）数据包到服务器，请求建立连接。这个数据包包含了客户端的初始序列号。
 
2. 第二次握手（SYN-ACK）：
 
- 服务器收到客户端的SYN数据包后，发送一个SYN-ACK（同步-确认）数据包作为响应。这个数据包包含了服务器的初始序列号和对客户端序列号的确认。
 
3. 第三次握手（ACK）：
 
- 客户端收到服务器的SYN-ACK数据包后，发送一个ACK（确认）数据包到服务器，确认收到服务器的序列号。至此，TCP连接建立完成，客户端和服务器可以开始数据传输。
 

TCP四次挥手的过程如下：

 
1. 第一次挥手（FIN）：
 
- 客户端发送一个FIN（结束）数据包到服务器，请求终止连接。这个数据包包含了客户端的序列号。
 
2. 第二次挥手（ACK）：
 
- 服务器收到客户端的FIN数据包后，发送一个ACK（确认）数据包作为响应，确认收到客户端的终止请求。
 
3. 第三次挥手（FIN）：
 
- 服务器完成所有的数据发送后，发送一个FIN数据包到客户端，请求终止连接。这个数据包包含了服务器的序列号。
 
4. 第四次挥手（ACK）：
 
- 客户端收到服务器的FIN数据包后，发送一个ACK数据包作为响应，确认收到服务器的终止请求。至此，TCP连接终止完成。
 

TCP三次握手和四次挥手的过程确保了TCP连接的可靠建立和终止，同时也处理了数据传输过程中的序列号同步和确认问题。

 

### 26\. TCP 为什么要三次握手，两次可以吗？

 

不可以，三次握手是为了防止已失效的连接请求突然又传送到了服务端，服务器会误以为是 新的连接请求而建立连接，造成服务器资源的浪费。

 

### 27.TCP拥塞控制是什么？常见的拥塞控制算法有哪些？

 

TCP拥塞控制是指通过调整数据发送速率来避免网络拥塞，防止网络过载。

 

常见拥塞控制算法

 
- 慢启动(slow Start):在连接开始时,TCP发送方的拥塞窗口(cwnd)初始设置为较小值(如1或2个报文段)。每当确认收到数据包时，拥塞窗口会指数级增长，直到达到一个阔值(ssthresh)，这时进入拥塞避免阶段。
 
- 拥塞避免(Congestion Avoidance):当拥基窗口达到ssthresh时,拥塞窗口的增长变为线性，每当确认数据包时，窗口增加1个报文段，以避免网络拥塞。
 
- \*\*快重传(\*\*Fast Retransmit):当发送方收到三个重复的ACK时,认为数据包丢失，立即重传丢失的数据包3. 而无需等待超时。
 
- \*\*快恢复(\*\*Fast Recovery):快恢复算法在快重传之后，减小拥塞窗口至ssthresh值的大小,然后重新进入拥4.塞避免阶段，而不是重新开始慢启动阶段
 

### 28\. 什么是流量控制？TCP是如何实现流量控制的？

 

流量控制是指控制发送端发送数据的速度，以防止接收端处理不过来。TCP使用滑动窗口实现流量控制:接收端通过窗口大小告诉发送端可以接受的字节量，发送端根据这个窗口大小控制发送速率。

 

### 29\. TCP如何保证传输的可靠性？

 

TCP（传输控制协议）通过一系列机制来保证数据传输的可靠性，主要包括以下几个方面：

 
1. 序列号和确认应答：
 
- TCP为每个传输的数据包分配一个序列号，接收方通过发送带有确认序列号的ACK（确认应答）来确认已成功接收数据。
 
- 如果发送方在设定的超时时间内未收到ACK，它会重新发送数据包。
 
2. 超时重传：
 
- TCP使用超时重传机制来处理丢失的数据包。如果发送方在一定时间内没有收到ACK，它会重新发送数据包。
 
- 超时时间通常基于往返时间（RTT）的估计，并使用加性增/乘性减算法来调整。
 
3. 滑动窗口流量控制：
 
- TCP使用滑动窗口机制来控制发送方的发送速率，确保接收方能够及时处理接收到的数据。
 
- 接收方通过TCP头部的窗口大小字段告知发送方其缓冲区的可用空间，发送方据此调整发送窗口大小。
 
4. 拥塞控制：
 
- TCP通过拥塞控制算法（如慢启动、拥塞避免、快速重传和快速恢复）来避免网络拥塞。
 
- 当检测到网络拥塞时，TCP会减小发送窗口大小，降低发送速率，直到网络状况改善。
 
5. 数据校验：
 
- TCP头部包含一个校验和字段，用于检测数据在传输过程中是否出现错误。
 
- 接收方会计算接收到的数据包的校验和，如果发现错误，则丢弃该数据包，并等待重传。
 
6. 连接管理：
 
- TCP使用三次握手建立连接，确保双方都准备好进行数据交换。
 
- 使用四次挥手来优雅地关闭连接，确保所有数据都被正确传输和接收。
 

通过这些机制的协同工作，TCP能够在一个不可靠的网络环境中提供可靠的端到端数据传输服务。

### 32\. 什么是 DHCP 协议

### 35\. 什么是 CDN

 

CDN（Content Delivery Network，内容分发网络）是一种分布式的网络架构，它利用多台服 务器和缓存机制来更快地将内容（如图像、视频、静态文件等）传输给用户。CDN 将原始 服务器上的内容复制到全球各地的多个节点上，当用户请求访问这些内容时，CDN 会根据 用户所在地域、网络环境等因素，自动选择距离用户最近的节点，从而实现更快速的响应和 更低的延迟。

 

### 36\. 解释 C/S、B/S、P2P

 

C/S(Client/Sever)架构是指客户端/服务器架构，由客户端和服务器组成。客户端是安装在用 户计算机上的应用程序，用于与服务器进行通信，并向用户提供服务。这里的“客户端”可以 是有 GUI （图形用户界面）的定制软件，也可以是浏览器，甚至可以是通过 SSH 访问服 务器的命令行脚本。而服务器则是一个中央计算机或计算机集群，负责处理客户端发送的请 求，并向客户端返回响应。

 

B/S(Browse/Sever)是 C/S 架构的一种特殊的实现形式

 

P2P(Peer to Peer)架构中每个节点（或者“对等体”）可以作为客户端和服务器的角色同时存在。 在 P2P 网络中，所有节点都可以直接通信，而不必依赖中央服务器进行中转。

- HTTPS (Hypertext Transfer Protocol Secure):在HTTP基础上加上SSL/TLS加密协议,提供安全的加密传输，确保数据的机密性和完整性。

### 39\. 在浏览器中输入URL到页面展示的过程是什么？

 

> 感兴趣的可以看这篇文章：[2.2 键入网址到网页显示，期间发生了什么？](https://www.xiaolincoding.com/network/1_base/what_happen_url.html#%E5%AD%A4%E5%8D%95%E5%B0%8F%E5%BC%9F-http)

 

在浏览器中输入URL到页面展示的过程涉及多个步骤，包括DNS解析、建立连接、发送请求、接收响应和渲染页面等。以下是详细的步骤：

 
1. 输入URL：
 
- 用户在浏览器的地址栏中输入URL，如http://www.example.com。
 
2. DNS解析：
 
- 浏览器需要将URL中的域名解析为IP地址。它首先检查本地DNS缓存，如果没有找到，则向操作系统查询，然后向配置的DNS服务器发送查询请求。
 
- DNS服务器收到查询请求后，会在其数据库中查找对应的IP地址。如果找到，则返回给浏览器；如果未找到，则向上级DNS服务器查询，直到找到为止。
 
3. 建立连接：
 
- 浏览器使用解析得到的IP地址，通过TCP协议与Web服务器建立连接。如果是HTTP/1.1或HTTP/2.0，则使用持久连接；如果是HTTPS，则还需要进行SSL/TLS握手过程。
 
4. 发送请求：
 
- 连接建立后，浏览器向Web服务器发送HTTP请求。请求中包含了URL、HTTP方法（如GET、POST等）、HTTP版本、请求头等信息。
 
5. 接收响应：
 
- Web服务器收到请求后，会根据请求内容生成HTTP响应。响应中包含了状态码、响应头和响应体等信息。
 
- 浏览器接收响应，并根据状态码判断请求是否成功。如果成功，则继续下一步；如果失败，则根据状态码进行相应的错误处理。
 
6. 渲染页面：
 
- 浏览器解析响应体中的HTML代码，构建DOM树。
 
- 浏览器解析CSS样式，构建CSSOM树。
 
- 浏览器将DOM树和CSSOM树合并，生成渲染树。
 
- 浏览器根据渲染树进行布局，计算出各个元素的几何信息。
 
- 浏览器将布局结果进行绘制，生成像素信息。
 
- 浏览器将像素信息显示在屏幕上，完成页面的渲染。
 
7. 处理资源：
 
- 在渲染过程中，浏览器会遇到各种资源，如图片、脚本、样式表等。对于这些资源，浏览器会发起新的HTTP请求，下载并处理它们。
 
- 资源下载完成后，浏览器会将它们应用到渲染树中，更新屏幕显示。
 
8. 交互与事件处理：
 
- 页面渲染完成后，浏览器会监听页面上的用户交互，如点击、滚动等，并触发相应的事件处理程序。
 
- 事件处理程序可以修改DOM树，触发重新渲染，实现动态的页面效果。
 

整个过程涉及网络通信、协议解析、页面渲染等多个方面，是浏览器和Web服务器共同协作的结果。

 

### 40\. GET和POST的区别是什么？

<table><tbody><tr><td><p>特性</p></td><td><p>GET</p></td><td><p>POST</p></td></tr><tr><td><p>数据传输方式</p></td><td><p>GET将请求参数附加在URL中，以查询字符串的形式发送。</p></td><td><p>POST将请求参数放在HTTP请求的消息体中发送。</p></td></tr><tr><td><p>数据大小限制</p></td><td><p>GET请求的URL长度有限制（通常受浏览器和服务器的限制），因此能传输的数据量较小。</p></td><td><p>POST请求的消息体大小没有固定限制，能传输的数据量较大。</p></td></tr><tr><td><p>数据安全性</p></td><td><p>GET请求的参数暴露在URL中，容易被截获或篡改，因此安全性较低。</p></td><td><p>POST请求的参数放在消息体中，不容易被截获或篡改，因此安全性较高。</p></td></tr><tr><td><p>缓存和书签</p></td><td><p>GET请求可以被缓存，也可以被收藏为书签。</p></td><td><p>POST请求通常不会被缓存，也不能被收藏为书签。</p></td></tr><tr><td><p>幂等性</p></td><td><p>GET请求是幂等的，即多次执行同一个GET请求，应该得到相同的结果，不会对服务器状态产生影响。</p></td><td><p>POST请求不是幂等的，即多次执行同一个POST请求，可能会对服务器状态产生不同的影响。</p></td></tr><tr><td><p>使用场景</p></td><td><p>GET请求通常用于请求数据，不会对服务器数据产生影响。</p></td><td><p>POST请求通常用于提交数据，可能会对服务器数据产生影响，如创建或更新资源。</p></td></tr></tbody></table>

### 41\. 什么是 DNS

 

DNS 是域名系统（Domain Name System）的缩写，用于将域名转换为 IP 地址。因为人们更 容易记住易于理解的域名，而不是一串数字的 IP 地址，所以 DNS 系统使人们更容易在网络 上访问网站、发送电子邮件等。

 

在 DNS 系统中，每个域名都对应一个唯一的 IP 地址。当你在浏览器中输入一个网址时，浏 览器首先会向 DNS 服务器发出请求，以获取该网址对应的 IP 地址。DNS 服务器会根据域 名系统的层级结构，将请求转发到相应的上级域名服务器，直到找到与域名对应的 IP 地址。

 

### 42\. 简述 DNS 解析过程

 
1. 浏览器先检查自身缓存、主机本地文件、中有没有对应的记录，如果有，直接返回结果。
 
2. 向本地域名服务器发送域名解析请求，如果本地域名服务器缓存了该域名的 IP 地址，它 将直接返回 IP 地址
 
3. 否则向根域名服务器发送解析请求，根域名服务器返回顶级域名服务器的 IP 地址
 
4. 本地域名服务器向 TLD 发送请求，顶级域名服务器返回权限域名服务器的 IP 地址。
 
5. 本地域名服务器向权限域名服务器发送请求，权限域名服务器返回该域名对应的 IP 地址 给本地域名服务器。
 
6. 本地域名服务器将该 IP 地址缓存，并将该 IP 地址返回给应用层。
 

### 43\. 什么是DNS缓存？作用是啥？

 

DNS缓存是一种存储DNS查询结果的机制，它可以在客户端（如浏览器、操作系统）或服务器端（如DNS服务器、负载均衡器）实现。DNS缓存的主要作用是提高DNS查询的效率，减少网络延迟，改善用户体验。

 

DNS缓存的工作原理

 

当客户端发起一个DNS查询请求时，DNS缓存会首先检查是否已经有该查询的结果。如果有，则直接返回缓存的结果，而无需向DNS服务器发送查询请求。如果没有，则将查询请求发送到DNS服务器，等待DNS服务器返回查询结果。收到查询结果后，DNS缓存会将结果存储起来，以便后续的查询请求可以直接使用缓存的结果。

 

DNS缓存的作用

 
1. 提高查询效率：
 
- 通过存储DNS查询结果，DNS缓存可以避免重复的DNS查询，从而提高查询效率，减少网络延迟。
 
2. 减轻DNS服务器负载：
 
- DNS缓存可以减少对DNS服务器的查询请求，从而减轻DNS服务器的负载，提高DNS服务器的性能。
 
3. 改善用户体验：
 
- DNS缓存可以加快网页加载速度，改善用户体验。因为DNS查询通常是网页加载过程中的瓶颈之一，通过缓存DNS查询结果，可以减少DNS查询的时间，从而加快网页加载速度。
 
4. 提高网络可靠性：
 
- DNS缓存可以在DNS服务器出现故障或网络连接不稳定时，提供一定的容错能力。因为即使DNS服务器不可用，DNS缓存仍然可以返回缓存的查询结果，从而保证网络服务的连续性。
 
5. 节省带宽：
 
- DNS缓存可以减少DNS查询请求的数量，从而节省网络带宽。因为DNS查询请求通常需要通过网络发送到DNS服务器，而DNS服务器的响应也需要通过网络发送回客户端。通过缓存DNS查询结果，可以减少这些网络传输，从而节省带宽。
 

总之，DNS缓存是一种重要的DNS优化技术，它可以通过存储DNS查询结果，提高DNS查询的效率，减少网络延迟，改善用户体验，同时还可以减轻DNS服务器负载，提高网络可靠性，节省带宽。
