## 2\. 机试代码的基本骨架

 

### 2.1 完整程序题

```cpp
#include <bits/stdc++.h>
using namespace std;


void solve() {
    // 读取一组数据并输出答案
}


int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);


    int T = 1;
    // cin >> T;  // 只有题目明确给出多组数据时才打开
    while (T--) {
        solve();
    }
    return 0;
}
```

注意：

 
- bits/stdc++.h 常见于 GNU C++ 环境，但并非标准头文件。模拟考试时确认编译器；不确定时使用标准头文件。
 
- 不要凭经验擅自读取 T。题目若是“读到 EOF”或“以 # 结束”，循环方式完全不同。
 
- 输出大小写、空格、换行必须严格匹配。
 

### 2.2 读到 EOF

```cpp
int x;
while (cin >> x) {
    // 处理一组数据
}
```

### 2.3 以特殊标记结束

```cpp
string s;
while (cin >> s && s != "#") {
    // 处理 s
}
```

### 2.4 行末不能有多余空格

```cpp
for (int i = 0; i < n; ++i) {
    if (i > 0) cout << ' ';
    cout << answer[i];
}
cout << '\n';
```

不要把 endl 当作默认换行。endl 还会强制刷新缓冲区，通常使用 '\\n' 更快。

## 3\. 锁定 main 与头文件补全：中大特色高频点

 

题目可能给出不可修改的 main，只允许提交 A1.hpp、A2.hpp 或类的声明。这时第一目标不是“自己设计一个更好的接口”，而是与给定代码逐字符匹配。

 

### 3.1 接口核对清单

 
- 类名大小写是否完全一致。
 
- 构造函数参数、const、引用是否一致。
 
- 返回值是否一致，例如必须返回 String&，不能写成 void。
 
- 成员函数是否需要 const。
 
- 主程序是否通过基类指针调用函数，若是，则基类函数要 virtual。
 
- 题目是否明确“不要提交 main”。
 
- 题目是否要求只能使用指针、不能使用数组或 STL。
 
- 输出应由哪个函数完成，不能重复输出。
 

### 3.2 头文件保护

```cpp
#ifndef A2_HPP
#define A2_HPP


class Num {
    // ...
};


#endif
```

也可以使用 #pragma once，但传统 include guard 兼容性最好。

 

### 3.3 在头文件中定义普通函数

 

同一个函数若在头文件中被多个源文件包含，可能发生重复定义。解决方式：

```cpp
inline int add(int a, int b) {
    return a + b;
}
```

类定义内部直接实现的成员函数隐含 inline。

 

### 3.4 不要滥用宏

 

2023 年回忆中提到 min、max 可能需要在另一个文件中处理，但回忆并不完整。不要因此背诵 #define min 或 #define max：

 
- 宏会污染标准库中的 std::min 和 std::max。
 
- main 里的 min、max 也可能是函数指针、枚举值或题目预留标识。
 
- 应先根据完整函数调用和编译错误推断所需声明。
 

考场上优先写类型安全的函数、函数对象或模板，只有题面明确要求宏时才用宏。

### 4.1 常用类型

看到下面情况，优先考虑 long long：

 
- n 达到 10^5，答案可能是 n²。
 
- 多条边权求和。
 
- 两个取模值相乘。
 
- 坐标接近 int 边界，先转 long long 再做减法和绝对值。

```cpp
long long dx = llabs(1LL * x1 - x2);
```

### 4.2 值传递、引用传递、const 引用

```cpp
void f1(vector<int> a);              // 复制整个数组
void f2(vector<int>& a);             // 可修改原数组
void f3(const vector<int>& a);       // 不复制，也不允许修改
```

默认选择：

 
- int、char、pair<int,int> 等小对象按值传递。
 
- vector、string、复杂对象按 const 引用传递。
 
- 需要修改调用者对象时使用非常量引用。
 

### 4.3 指针基础

```cpp
int x = 10;
int* p = &x;
*p = 20;       // 修改 x


int* a = new int[n];
delete[] a;
a = nullptr;
```

必须配对：

 
- new 对应 delete。
 
- new\[\] 对应 delete\[\]。
 

高频错误：

 
- delete\[\] 后再次访问。
 
- 两个对象保存同一个裸指针，析构时重复释放。
 
- 删除链表节点后继续使用该节点。
 
- 忘记处理 nullptr。
 

### 4.4 const 的两个常见位置

```cpp
const int* p1;       // 不能通过 p1 修改所指对象
int* const p2 = &x;  // p2 本身不能改指向


int size() const;    // 成员函数承诺不修改对象状态
```

如果 main 持有 const 对象或 const 引用，只有 const 成员函数能被调用。

## 5\. 类与对象：最高优先级

 

### 5.1 构造函数与初始化列表

```cpp
class Point {
private:
    int x_;
    int y_;


public:
    Point() : x_(0), y_(0) {}
    Point(int x, int y) : x_(x), y_(y) {}
};
```

初始化列表比“先默认构造再赋值”更直接，并且以下成员必须在初始化列表中初始化：

 
- const 成员。
 
- 引用成员。
 
- 没有默认构造函数的成员对象。
 
- 基类部分。
 

成员实际初始化顺序由“成员声明顺序”决定，不由初始化列表书写顺序决定。

 

### 5.2 默认浅拷贝为什么危险

```cpp
class BadArray {
    int* data;
    int n;
};
```

编译器生成的拷贝只会复制 data 中的地址：

```text
对象 a.data ─┐
             ├──> 同一块动态内存
对象 b.data ─┘
```

后果：

 
- 修改 b 可能影响 a。
 
- 两个析构函数都 delete\[\] 同一地址，发生重复释放。
 
- 赋值时旧内存可能泄漏。
 

### 5.3 Rule of Three：考试必会

 

只要类自己管理裸指针资源，通常要同时写：

 
1. 析构函数。
 
2. 拷贝构造函数。
 
3. 拷贝赋值运算符。

```cpp
class IntArray {
private:
    int* data_;
    int size_;


public:
    IntArray() : data_(nullptr), size_(0) {}


    explicit IntArray(int n)
        : data_(n > 0 ? new int[n]{} : nullptr), size_(n) {}


    IntArray(const IntArray& other)
        : data_(other.size_ > 0 ? new int[other.size_] : nullptr),
          size_(other.size_) {
        if (size_ > 0) {
            copy(other.data_, other.data_ + size_, data_);
        }
    }


    IntArray& operator=(const IntArray& other) {
        if (this == &other) return *this;


        int* new_data =
            other.size_ > 0 ? new int[other.size_] : nullptr;
        if (other.size_ > 0) {
            copy(other.data_, other.data_ + other.size_, new_data);
        }


        delete[] data_;
        data_ = new_data;
        size_ = other.size_;
        return *this;
    }


    ~IntArray() {
        delete[] data_;
    }
};
```

赋值运算符的关键点：

 
- 参数用 const IntArray&，避免额外复制。
 
- 返回 IntArray&，支持 a=b=c。
 
- 处理自赋值 a=a。
 
- 先成功申请新内存，再释放旧内存，异常安全性更好。
 
- 不要忘记 return \*this。
 

### 5.4 拷贝构造与赋值的区别

```cpp
IntArray a(10);
IntArray b = a;  // b 刚创建：拷贝构造


IntArray c(5);
c = a;           // c 已存在：拷贝赋值
```

### 5.5 Rule of Five 与 Rule of Zero

 

C++11 还可以实现移动构造和移动赋值，形成 Rule of Five。但中大回忆题的核心通常是深拷贝，先把 Rule of Three 写稳。

 

工程代码更推荐 vector、string、unique\_ptr 等自动管理资源，即 Rule of Zero；但如果题面要求手写指针，就必须按题意完成。

## 6\. 继承、多态、虚函数与虚继承

 

### 6.1 运行时多态成立的三个条件

 
1. 存在继承关系。
 
2. 基类函数声明为 virtual。
 
3. 通过基类指针或基类引用调用。

```cpp
class Animal {
public:
    virtual void shout() const = 0;
    virtual int getType() const = 0;
    virtual ~Animal() = default;
};


class Dog : public Animal {
public:
    void shout() const override {
        cout << "W\n";
    }


    int getType() const override {
        return 0;
    }
};
```

override 强烈建议写：

 
- 编译器会检查是否真的重写。
 
- 能发现参数、const、返回类型写错等问题。
 

### 6.2 为什么基类析构函数要 virtual

```cpp
Animal* p = new Dog;
delete p;
```

如果 Animal 的析构函数不是 virtual，通过基类指针删除派生对象会产生未定义行为，派生类资源可能无法释放。

 

经验规则：一个类只要被设计成多态基类，就给它虚析构函数。

 

### 6.3 纯虚函数与抽象类

```cpp
virtual void shout() const = 0;
```

包含纯虚函数的类是抽象类，不能直接创建对象，但可以声明指针和引用。

 

### 6.4 对象切片

```cpp
Dog dog;
Animal animal = dog;  // 若 Animal 可实例化，会切掉 Dog 部分
```

多态对象应通过指针或引用保存。若要容纳不同派生对象，常用 vector<Animal\*>；现代 C++ 更推荐 vector<unique\_ptr\>，但题目可能限制接口。

 

### 6.5 菱形继承

```text
       Base
      /    \
   Left   Right
      \    /
       Final
```

普通继承会让 Final 中出现两份 Base。解决方式：

```cpp
class Left  : virtual public Base {};
class Right : virtual public Base {};
class Final : public Left, public Right {};
```

准确语法是“在继承说明中使用 virtual”。不是给“类前面加 virtual”。

 

虚析构与虚继承解决的是两件不同的事：

 
- virtual ~Base()：通过基类指针正确析构。
 
- virtual public Base：菱形继承中共享一份 Base 子对象。
 

### 6.6 构造顺序

 

构造顺序固定为：

 
1. 虚基类。
 
2. 非虚基类，按派生类继承列表中的声明顺序。
 
3. 成员对象，按成员声明顺序。
 
4. 当前类构造函数体。
 

析构顺序完全相反。

 

最底层派生类负责构造虚基类：

```cpp
class Base {
public:
    explicit Base(int x) {}
};


class Left : virtual public Base {
public:
    Left() : Base(1) {}
};


class Final : public Left {
public:
    Final() : Base(42), Left() {}  // 实际由 Final 构造 Base
};
```

构造顺序题不要看初始化列表的排列顺序猜答案，要看继承和成员的声明顺序。

## 7\. STL 必备清单

 

### 7.1 vector

```cpp
vector<int> a(n);
a.push_back(x);
a.pop_back();
int n = static_cast<int>(a.size());
sort(a.begin(), a.end());
sort(a.rbegin(), a.rend());
```

常见错误：

 
- 空 vector 上调用 back 或 pop\_back。
 
- 下标越界。
 
- 遍历时 push\_back 导致迭代器失效。
 

### 7.2 string

```cpp
string s;
cin >> s;            // 不读空格
getline(cin, s);      // 读取整行


reverse(s.begin(), s.end());

    // 没找到
}
```

cin >> 后立刻 getline 时，先清理上一行残留换行：

```cpp
cin.ignore(numeric_limits<streamsize>::max(), '\n');
getline(cin, s);
```

### 7.3 map 与 unordered\_map

```cpp
unordered_map<int, int> freq;
++freq[x];
```

### 7.5 stack、queue、priority\_queue

```cpp
stack<int> st;
queue<int> q;


priority_queue<int> max_heap;
priority_queue<int, vector<int>, greater<int>> min_heap;
```

字典序最小拓扑排序需要 min\_heap；普通 Dijkstra 也通常用最小堆。

 

### 7.6 自定义排序

```cpp
sort(a.begin(), a.end(), [](const auto& lhs, const auto& rhs) {
    if (lhs.first != rhs.first) return lhs.first < rhs.first;
    return lhs.second > rhs.second;
});
```

比较器必须保持严格弱序。相等元素之间应返回 false，不能写 <=。

## 8\. 手写单链表：虚拟头节点是核心

 

### 8.1 节点定义

```cpp
struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int x) : val(x), next(nullptr) {}
};
```

链表题最容易错的是头节点。虚拟头节点 dummy 能统一“修改头节点”和“修改中间节点”：

```text
dummy -> head -> ...
```

### 8.2 删除所有等于 target 的节点

```cpp
ListNode* deleteAll(ListNode* head, int target) {
    ListNode dummy(0);
    dummy.next = head;
    ListNode* prev = &dummy;


    while (prev->next) {
        if (prev->next->val == target) {
            ListNode* doomed = prev->next;
            prev->next = doomed->next;
            delete doomed;
        } else {
            prev = prev->next;
        }
    }
    return dummy.next;
}
```

删除后 prev 不要立刻向后移动，因为新的 prev->next 仍可能等于 target。

 

### 8.3 两两交换

 

每次维护 prev、first、second：

```text
prev -> first -> second -> next
prev -> second -> first -> next
```

### 8.4 区间反转

 

常用“头插法”：固定区间第一个节点 first，每次把 first 后面的节点摘下，插到区间最前端。

 

边界：

 
- left == right。
 
- head == nullptr。
 
- left 或 right 超过链表长度。
 
- 位置是从 0 还是从 1 开始。
 

### 8.5 有序插入

```cpp
ListNode* insertSorted(ListNode* head, int value) {
    ListNode dummy(0);
    dummy.next = head;
    ListNode* prev = &dummy;


    while (prev->next && prev->next->val < value) {
        prev = prev->next;
    }


    ListNode* node = new ListNode(value);
    node->next = prev->next;
    prev->next = node;
    return dummy.next;
}
```

若题目规定相同值的稳定顺序，需要决定循环条件使用 < 还是 <=。

## 9\. 排序、哈希与字符串高频题

 

### 9.1 相对名次：保留原顺序

 

通用模式：

 
1. 复制原数组。
 
2. 对副本排序。
 
3. 建立“值 → 排名”映射。
 
4. 遍历原数组输出。
 

若成绩可能重复，不能简单用“成绩 → 唯一名次”，必须按题意处理并列排名，或排序“值 + 原下标”。

 

### 9.2 字符串唯一映射：必须双向检查

 

只检查 A 中每个字符是否固定映射到 B 不够，还必须保证 B 中不同字符不能映回同一个 A 字符。

 

例如 aa → bc 在单向检查时就会冲突；ab → cc 则需要反向检查才能排除。

```cpp
bool isomorphic(const string& a, const string& b) {
    if (a.size() != b.size()) return false;
    unordered_map<char, char> f, g;


    for (int i = 0; i < static_cast<int>(a.size()); ++i) {
        char x = a[i], y = b[i];
        if (f.count(x) && f[x] != y) return false;
        if (g.count(y) && g[y] != x) return false;
        f[x] = y;
        g[y] = x;
    }
    return true;
}
```

### 9.3 循环字符串

 

s1 的所有循环移位都出现在 s1+s1 中。

```cpp
bool ok = s2.size() <= s1.size() &&
          (s1 + s1).find(s2) != string::npos;
```

若题目要求“s2 恰好是 s1 的某个循环移位”，还必须要求两者长度相等。

 

### 9.4 克隆子串 BB

 

长度不超过 50 时直接枚举：

 
- B 的长度 len。
 
- 起点 start。
 
- 比较两段长度为 len 的连续子串。
 

复杂度 O(n³) 对 n≤50 足够。不要看到字符串就立刻上 KMP。

 

### 9.5 反转字符串配对

 

若每个字符串最多使用一次：

 
1. 统计每个字符串出现次数。
 
2. 对 s 求 reverse(s)。
 
3. 与反串配对并同时减少计数。
 

回文串 s==reverse(s) 时，一次配对需要两个相同字符串，贡献 floor(count/2)。

 

### 9.6 段式回文

 

从两端累积最短前缀与后缀，一旦相等立刻切段，可以最大化段数。

 

实现时注意：

 
- 右侧片段要在前面插入字符，保持原顺序。
 
- 中间剩余部分整体算一段。
 
- 若字符串很长，频繁头插可能较慢，可使用哈希或索引比较优化。

## 10\. DFS、BFS 与网格题

 

### 10.1 四方向模板

```cpp
const int dr[4] = {-1, 1, 0, 0};
const int dc[4] = {0, 0, -1, 1};


bool inside(int r, int c, int n, int m) {
    return 0 <= r && r < n && 0 <= c && c < m;
}
```

### 10.2 DFS：连通块、路径、回溯

```cpp
void dfs(int r, int c) {
    visited[r][c] = true;


    for (int d = 0; d < 4; ++d) {
        int nr = r + dr[d];
        int nc = c + dc[d];
        if (!inside(nr, nc, n, m)) continue;
        if (wall[nr][nc] || visited[nr][nc]) continue;
        dfs(nr, nc);
    }
}
```

标记 visited 的时间应在入队或进入递归时，而不是退出时，否则同一点可能被重复加入。

 

### 10.3 BFS：无权最短路

```cpp
queue<pair<int, int>> q;
dist[sr][sc] = 0;
q.push({sr, sc});


while (!q.empty()) {
    auto [r, c] = q.front();
    q.pop();


    for (int d = 0; d < 4; ++d) {
        int nr = r + dr[d];
        int nc = c + dc[d];
        if (!inside(nr, nc, n, m)) continue;
        if (grid[nr][nc] == 'X' || dist[nr][nc] != -1) continue;
        dist[nr][nc] = dist[r][c] + 1;
        q.push({nr, nc});
    }
}
```

### 10.5 训练机器人：树形迷宫的分岔计数

 

题目若保证任意两个空格间只有一条简单路径，空格图就是树。

 

在路径上的当前节点，排除父节点后，可走邻居数量大于 1 才是分岔点。要先确认题目中的“没走过”是否仅指父节点，还是要求完整 visited；若题面不保证树，则必须使用 visited。

 

### 10.6 蜡烛照明模拟

 

稳妥方法：

 
1. 建立 lit 数组。
 
2. 对每支蜡烛向四个方向扫描。
 
3. 遇到边界或障碍停止。
 
4. 经过空点则标记 lit。
 
5. 最后统计未照亮空点。
 

复杂度 O(蜡烛数 × (n+m))。若数据很大，再考虑按行列预处理。

## 11\. 并查集与图连通性

 

### 11.1 模板

```cpp
class DSU {
    vector<int> parent, size;


public:
    explicit DSU(int n) : parent(n), size(n, 1) {
        iota(parent.begin(), parent.end(), 0);
    }


    int find(int x) {
        if (parent[x] == x) return x;
        return parent[x] = find(parent[x]);
    }


    bool unite(int a, int b) {
        a = find(a);
        b = find(b);
        if (a == b) return false;
        if (size[a] < size[b]) swap(a, b);
        parent[b] = a;
        size[a] += size[b];
        return true;
    }
};
```

两项优化：

 
- 路径压缩。
 
- 按大小或按秩合并。
 

### 11.2 适用场景

 
- 大量“连接 u、v”和“查询 u、v 是否连通”。
 
- Kruskal 最小生成树。
 
- 判断加入一条无向边是否形成环。
 

如果只查询一次连通性，DFS/BFS 通常更直接。

## 12\. 二叉树合法性

 

给出每个节点的左右孩子编号，判断是否形成一棵合法二叉树，通常检查：

 
1. 每个节点入度不超过 。
 
2. 恰好有一个入度为 0 的根。
 
3. 从根能访问所有节点。
 
4. 不存在环。
 
5. 左右孩子编号合法，且按题意处理重复孩子。
 

可以在 DFS 中使用三色标记：

 
- 0：未访问。
 
- 1：正在递归栈中。
 
- 2：已完成。
 

遇到颜色 1 的节点说明有环。仅检查“一个根”不够，因为可能存在与根不连通的环。

## 13\. 拓扑排序

 

Kahn 算法：

 
1. 统计每个点入度。
 
2. 所有入度为 0 的点入队。
 
3. 每次取出一个点，删除它的出边。
 
4. 新的入度 0 节点入队。
 
5. 最终取出的点数小于 n，则有环。
 

字典序最小拓扑序必须使用小根堆：

```cpp
priority_queue<int, vector<int>, greater<int>> ready;
```

核心模板：

```cpp
vector<int> order;
while (!ready.empty()) {
    int u = ready.top();
    ready.pop();
    order.push_back(u);


    for (int v : graph[u]) {
        if (--indegree[v] == 0) {
            ready.push(v);
        }
    }
}


if (static_cast<int>(order.size()) < n) {
    cout << "It's not a DAG!\n";
}
```

重边处理：

 
- 若把每条输入边都存入邻接表，同时每条边都增加一次入度，Kahn 算法仍能正确配对递减。
 
- 若题意把重边视为同一约束，也可以先去重；不要只去重邻接表却仍重复增加入度。
 

原回忆材料的“拓扑排序”段落混入了克隆子串解法，不能照抄；拓扑排序应使用上述入度算法。

## 14\. 最短路与最大瓶颈路

 

### 14.1 Dijkstra 的适用条件

 
- 单源最短路。
 
- 边权非负。
 
- 邻接表 + 优先队列复杂度 O((n+m)log n)。

```cpp
using State = pair<long long, int>;
priority_queue<State, vector<State>, greater<State>> pq;


dist[source] = 0;
pq.push({0, source});


while (!pq.empty()) {
    auto [du, u] = pq.top();
    pq.pop();
    if (du != dist[u]) continue;


    for (auto [v, w] : graph[u]) {
        if (dist[v] > du + w) {
            dist[v] = du + w;
            pq.push({dist[v], v});
        }
    }
}
```

不能用 Dijkstra 处理负权边。

 

### 14.2 最大瓶颈路

 

目标不是最小化边权和，而是：

```text
最大化：一条路径上最小边权
```

定义 best\[v\] 为从起点到 v 能获得的最大瓶颈值。

 

转移：

```cpp
candidate = min(best[u], edgeWeight);
best[v] = max(best[v], candidate);
```

使用最大堆，每次扩展当前 best 最大的点。这正是“道路能见度”类题目的核心。

 

注意最终输出是否需要加一或减一，要根据阈值的严格不等式判断。例如题目说“边权 < w 不能走”和“边权 <= w 不能走”，临界答案不同。

## 15\. 最小生成树

 

### 15.1 识别信号

 

题目要求：

 
- 所有点连通。
 
- 可以选择部分边。
 
- 总边权最小。
 

这通常就是 MST。

 

### 15.2 Prim 与 Kruskal 的选择

<table><tbody><tr><td><p>图类型</p></td><td><p>推荐</p></td></tr><tr><td><p>完全图或稠密图，边可现场计算</p></td><td><p>O(n²) Prim</p></td></tr><tr><td><p>稀疏图，直接给出 m 条边</p></td><td><p>Kruskal 或堆优化 Prim</p></td></tr></tbody></table>

2025 年曼哈顿距离连点题是完全图，n≤1000 时不必显式保存约 50 万条边，直接 O(n²) Prim。

```cpp
vector<long long> minEdge(n, INF);
vector<bool> used(n, false);
minEdge[0] = 0;
long long answer = 0;


for (int step = 0; step < n; ++step) {
    int u = -1;
    for (int v = 0; v < n; ++v) {
        if (!used[v] && (u == -1 || minEdge[v] < minEdge[u])) {
            u = v;
        }
    }


    used[u] = true;
    answer += minEdge[u];


    for (int v = 0; v < n; ++v) {
        if (!used[v]) {
            long long w =
                llabs(1LL * x[u] - x[v]) +
                llabs(1LL * y[u] - y[v]);
            minEdge[v] = min(minEdge[v], w);
        }
    }
}
```

### 15.3 Kruskal

 

步骤：

 
1. 所有边按权值升序。
 
2. 若一条边两端不在同一集合，则选择它并 unite。
 
3. 选够 n-1 条边结束。
 

核心依赖并查集。

## 16\. 贪心题

 

### 16.1 相邻元素不能相同

 

设最大出现次数为 maxFreq。存在合法排列的充要条件：

```text
maxFreq <= ceil(n/2) = (n+1)/2
```

直觉：数量最多的元素先摆开，它们之间有 maxFreq-1 个空隙，其他元素必须足以隔开。

 

### 16.2 括号最少交换

 

回忆题说可以通过“不匹配右括号数量”得到答案，但必须先确认交换定义：

 
- 任意两个位置交换：常见答案为 ceil(最大失衡量/2) 或基于失衡右括号数量计算。
 
- 只能交换相邻字符：答案通常是把后面的左括号移动过来，计算移动距离，公式完全不同。
 
- 左右括号总数不相等：无论怎样交换都不可能合法。
 

不要只背“除以 2 向上取整”，先读清交换范围。

 

### 16.3 段式回文

 

从两侧寻找最短相同块，一旦匹配立即切下。因为更短的外层块能留下更多字符继续分段，符合局部最优到全局最优。

 

### 16.4 贪心证明的三种常见方式

 
- 交换论证：把最优解调整为贪心选择，不会变差。
 
- 反证法：若不选当前最优会矛盾。
 
- 上下界吻合：构造达到理论上界的方案。
 

考试中至少写清“为什么立即选择不会损失未来选择”。

## 17\. 动态规划与记忆化搜索

 

### 17.1 写 DP 前的四个问题

 
1. 状态表示什么？
 
2. 从哪些旧状态转移？
 
3. 初始状态是什么？
 
4. 按什么顺序计算，答案在哪个状态？
 

### 17.2 记忆化搜索

```cpp
long long dfs(int day, int floor1, int floor2) {
    if (day == D) {
        return floor1 == target1 && floor2 == target2;
    }


    long long& ans = memo[day][floor1][floor2];
    if (ans != -1) return ans;
    ans = 0;


    for (int next1 : moves(floor1)) {
        for (int next2 : moves(floor2)) {
            ans += dfs(day + 1, next1, next2);
        }
    }
    return ans;
}
```

这个框架适合 2024 保研回忆中的楼层方案数问题，但 moves、是否允许停留、两人能否同层等规则必须按原题补充。

 

状态规模估算：O(D×H²)。若 D、H 很大，需要压缩或寻找矩阵快速幂等方法。

 

### 17.3 区间 DP：括号染色

 

关键步骤：

 
1. 用栈预处理每个左括号匹配的右括号。
 
2. dp\[l\]\[r\]\[a\]\[b\] 表示区间 \[l,r\] 两端颜色为 a、b 的方案数。
 
3. 若 match\[l\]==r，则 \[l,r\] 是一对外层括号包住内部。
 
4. 若 match\[l\]<r，则区间由两个并列合法括号段组成，在 match\[l\] 处分割。
 
5. 合并时检查相邻括号颜色是否合法。
 

颜色可设：

 
- 0：不染。
 
- 1：红。
 
- 2：蓝。
 

匹配括号的合法组合应严格按题意枚举。相邻颜色规则也应单独写成函数，避免把“两个都不染”误判为冲突。

 

### 17.4 不同子序列计数为什么难

 

普通子序列 DP 统计的是“选择位置的方法数”，而题目可能要求“不同结果字符串数”。例如 ()() 中，用不同位置可以得到相同的 ()。

 

常见去重方法：

 
- 记录字符上一次出现位置并扣除重复。
 
- 预处理 next occurrence，让每个目标字符串只沿一种规范路径生成。
 
- 使用自动机状态。
 

这类题属于冲高分内容。先掌握状态去重思想，不建议只背一份复杂代码。

## 18\. 图上最大异或：只在题意完整时套线性基

 

2024 保研回忆只有“城市美丽值、无向道路、从 1 出发、经过城市值异或、求最大值”，缺少以下关键条件：

 
- 路径是否允许重复经过城市和道路。
 
- 城市值重复经过时是否重复计入。
 
- 必须到达指定终点，还是可在任意城市停止。
 
- 求简单路径还是任意游走。
 

这些条件会改变问题本质。

 

若完整题面是经典“边权异或路径”，通常做法是：

 
1. DFS 求从起点到每点的树上前缀异或。
 
2. 每遇到非树边，得到一个环异或值。
 
3. 把环异或值插入 XOR 线性基。
 
4. 用线性基最大化到目标的前缀异或。
 

但“点权路径”需要先做正确变换，不能直接照搬边权模板。考场上看到回忆相似题时，应先用小图手算重复经过的影响，再决定是否是线性基。

## 20\. 高频易错清单

 

### 语言与接口

 
- 忘记 const，导致无法重写或无法被 const 对象调用。
 
- 基类函数参数不同，实际变成重载而不是重写。
 
- 忘记 virtual 析构。
 
- 拷贝赋值返回 void，而题目需要 Class&。
 
- new\[\] 却使用 delete。
 
- 自赋值时先释放了自己的数据，再从已释放内存复制。
 
- 在头文件中重复定义非 inline 全局函数或全局变量。
 
- 题目说不要 main，却提交了 main。
 

### STL

 
- 把 priority\_queue 默认的大根堆当成小根堆。
 
- string::find 的返回值与 -1 比较，最好使用 string::npos。
 
- 比较器写 <=。
 
- unordered\_map 使用 operator\[\] 判断存在性，意外插入。
 
- size() 返回无符号类型，与负数比较。
 

### 搜索与图论

 
- DFS/BFS 入队后才标记，导致重复入队。
 
- 忘记清空多组数据的全局数组和邻接表。
 
- 无向边只加了一个方向。
 
- Dijkstra 使用 int 保存距离和。
 
- Dijkstra 没有丢弃优先队列中的旧状态。
 
- 拓扑排序用普通队列却要求字典序最小。
 
- Prim 没有用 long long 累加。
 

### 链表

 
- 删除头节点后没有更新 head。
 
- 删除节点后访问已经释放的指针。
 
- 反转后丢失后半段链表。
 
- left/right 的下标起点理解错误。

## 21\. 考场解题流程

 

### 第 1 步：先读提交要求

 

圈出：

 
- 提交完整程序还是只补头文件。
 
- 是否禁止 main。
 
- 函数签名和类名。
 
- 可用语言标准。
 
- 多组数据形式。
 

### 第 2 步：用样例反推接口与边界

 

对 OOP 题先画：

 
- 类继承图。
 
- 哪些函数需要 virtual。
 
- 哪个类拥有资源。
 
- 构造与析构顺序。
 

对算法题先写：

 
- n、m 范围。
 
- 图是有向还是无向。
 
- 边权是否为负。
 
- 是否要求字典序。
 
- 是否允许重边、自环、重复访问。
 

### 第 3 步：先交可编译版本

 

如果支持部分分：

 
- 先实现构造函数和最基本输出。
 
- 先处理 n=1、空链表、无边图。
 
- 复杂题先写 O(n²) 或暴力版本，只要数据范围有部分小点。
 
- 保证函数都有返回值，不留未定义符号。
 

### 第 4 步：补边界

 

固定检查：

 
- 0、1、空。
 
- 全相同、全不同。
 
- 已有序、逆序。
 
- 头尾节点。
 
- 图不连通、只有一个点、重边、自环。
 
- 答案溢出。
 

### 第 5 步：最后 5 分钟只做编译级检查

 
- 括号和分号。
 
- include。
 
- 名字大小写。
 
- return。
 
- 输出格式。
 
- 是否误提交 main。

## 25\. 最后一页速记

```text
深拷贝：
析构 + 拷贝构造 + 拷贝赋值
operator=：自赋值检查、先申请后释放、返回 *this


多态：
继承 + virtual + 基类指针/引用
多态基类必须虚析构
override 防止“以为重写，实际重载”


虚继承：
class Left : virtual public Base
解决菱形继承的两份 Base


构造顺序：
虚基类 -> 非虚基类声明顺序 -> 成员声明顺序 -> 自身


链表：
先画指针，优先 dummy
删除后不要访问已释放节点


图：
连通性：DFS/BFS/DSU
无权最短路：BFS
非负权最短路：Dijkstra
最大化路径最小边：最大瓶颈路
全部连通且总权最小：MST
有向依赖与判环：拓扑排序


堆：
priority_queue 默认大根堆
小根堆加 greater


复杂度：
先看数据范围，再决定算法
总权值、距离和、方案乘法优先 long long


考试：
先匹配接口，再写逻辑
先交能编译版本，再补完整边界
输出大小写、空格、换行逐项检查
```

这份笔记的合理使用顺序是：先掌握第 3—8 节，确保前三题和手写数据结构；再掌握第 9—16 节，争取中档算法题；最后用第 17—18 节冲击动态规划和异或类难题。
